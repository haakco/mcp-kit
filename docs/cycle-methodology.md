# MCP E2E Cycle Methodology

**Last verified:** 2026-05-01

This methodology is the reusable QA loop for MCP servers built with `mcp-kit`. It verifies the running server through live MCP channels, not only unit tests.

## Goal

At the end of each cycle, the team should know whether the deployed MCP server works for real clients:

- OAuth discovery and dynamic client registration work.
- PKCE login and token exchange work.
- Streamable HTTP handshake works.
- Tools, resources, and prompts render and execute with valid JSON-RPC envelopes.
- Inspector and at least one MCP-aware coding client can use the server.

## Pre-Flight

Run these before opening a cycle:

1. Run the consumer's normal test and lint gates.
2. Run MCP-specific transport, OAuth, and registry tests.
3. Check source drift since the previous cycle close.
4. Confirm no generated byproducts are present in the cycle docs tree.
5. Confirm the live dev endpoint is reachable.
6. Confirm the MCP endpoint rejects anonymous requests with `401`.
7. Confirm OAuth metadata endpoints return canonical JSON.
8. Choose live verification channels for the cycle.

Channel guidance:

| Channel | Purpose |
|---|---|
| `curl` | Required live HTTP probe for every cycle. |
| MCP Inspector | Required schema/rendering check before publishing. |
| Claude Code or equivalent | Required end-user client check before publishing. |

## Reset

At cycle start:

1. Archive the previous cycle's active state.
2. Redact tokens before committing archived state.
3. Recreate empty active checklist, findings, and session-state files.
4. Reset sub-plan or phase statuses to `NOT STARTED`.
5. Record the new cycle ID and expected audit tier.

Do not append a new cycle's findings to the previous cycle. Archived cycles are immutable evidence.

## Audit Tiers

Choose the audit tier from source drift:

| Drift signal | Tier | Required depth |
|---|---|---|
| No MCP source changes | Carry-forward | Smoke bootstrap and closeout; cite existing green automation. |
| Small localized MCP changes | Smoke | Live-probe changed surfaces; carry forward untouched surfaces. |
| Broad MCP changes or core transport/auth changes | Full | Exercise every phase, every surface, and required real-client gates. |

Record the tier in the cycle summary and in each phase closeout.

## Phase Workflow

Run phases in order. Do not begin the next phase until the current one is closed.

Each phase follows the same loop:

1. Read active session state.
2. Refresh or mint credentials if needed.
3. Initialize a fresh MCP session.
4. Run happy-path probes.
5. Run negative-path probes.
6. Run filter/argument coverage where applicable.
7. Capture real-client evidence when the phase requires it.
8. File findings with reproducible commands.
9. Re-verify fixed findings before closing.
10. Update phase status and session state.

## Required Bootstrap Probe

Every cycle needs a fresh OAuth client and bearer token unless the server runs in explicit local unauthenticated mode.

Bootstrap proves:

- Dynamic registration accepts a public PKCE client.
- PKCE verifier/challenge generation is valid.
- Authorization and consent preserve requested scopes.
- Token exchange returns access and refresh tokens.
- `initialize -> notifications/initialized -> tools/list` works over Streamable HTTP.

## Required Closeout

A cycle is closed only when:

- Test and lint gates are green.
- Every phase is `DONE` or explicitly `DEFERRED`.
- Findings have stable IDs and reproduction commands.
- Real-client gates are passed or explicitly deferred with owner/date.
- Token-bearing artifacts are redacted.
- A cycle summary records coverage, findings, and carryover.

## Evidence Rules

- Save raw HTTP captures for protocol failures.
- Save parsed JSON only after preserving raw output.
- Do not commit access tokens, refresh tokens, authorization codes, cookies, or client secrets.
- Before filing SDK or protocol bugs, rebuild the server from `HEAD` and re-capture the symptom.
